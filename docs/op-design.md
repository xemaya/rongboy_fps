# 开场片和主界面：准则、分镜、检查

这份文档管两件事：游戏的开场片（OP）和主界面。先是准则（从人做预告片、定格动画、标题画面的经验里整理的），再是这一版的分镜和对照检查。
镜头本身怎么拍（景别、轴线、剪辑）仍以引擎仓库的 `cine-engine/docs/film-grammar.md` 为准，故事怎么想以 `cine-engine/docs/story-design.md` 为准，这里只写它们没有的部分。

每做完一轮，把学到的写回第 1、2 节，并在第 6 节记一行。

## 1. 开场片准则

### 1.1 结构

- 骨架：冷开场 → 介绍（基本玩法）→ 升级（玩法被加码）→ 高潮（变体、规模）→ 按钮（最后一个笑点或反转，可选）。小游戏每一段可以只有几秒。（Lieu）
- 冷开场是 5–10 秒自成一体的一小段，要抛出一个等着被回答的问题。前 6 秒决定观众看不看下去。（Lieu）
- 第一个画面不要用怼脸的特写：毛绒僵尸的脸撑满画面不好看，停得久更难受。用中景起，让人先看见它整个站在屋里的样子。（本项目：用户对第一版的意见）
- 先让人认出这是什么游戏，马上给它独有的东西，别先罗列和别人一样的。（Lieu）
- 开头的空镜最多两三个；慢慢摇过场景的开头看不出游戏类型。（Lieu）
- 按游戏教玩家的顺序排：基础 → 加一层复杂 → 展示广度。最炫的压到最后。（Lieu）
- 核心循环要演完整。这个游戏的循环是：潜行 → 从背后一球 → 响声惊动别的。（Lieu，本项目）
- 要有峰有谷。全程高能等于没有高能。（Lieu）
- 标题卡只用一张，至少停几秒，字要够读两遍。（Lieu）
- 标题卡上只放名字。第二版在名字下面加了一句"嘘——别吵醒它们。"，用户让删掉：片子已经演过这件事，再写一遍是多余的。（本项目：用户对第二版的意见）
- OP 和预告的区别：预告是给还没点进来的人看的，OP 是给已经打开游戏的人看的，所以可以定调、认人、许诺。但"看了想玩"的标准不变。（前半句是 ANN 专栏，后半句是本项目的推论）

### 1.2 镜头

- 一个"动词"镜头里要有变化、因、果，一个镜头只讲一件事。可以一镜给因、下一镜给果。（Lieu）
- 游戏预告比电影预告切得少：镜头要长到能看懂玩法。（Lieu）
- 清晰先于风格。花哨到分不清是剪辑还是玩法就过了。（Lieu）
- 有东西在动时镜头不动；一个镜头最多一次慢运镜；不做手持晃动。（本项目：用户看频繁运镜会头晕，见引擎准则第 2 节）

### 1.3 跟着音乐

- 先有音乐再剪。音乐的段落就是片子的段落。（Lieu；段落怎么对应是本项目的做法）
- 让动作落在拍点上，不是让切点落在拍点上。切点全压拍会像幻灯片。（Lieu）
- 先盘点游戏里自带节奏的动作（这里是一蹦一蹦地走、开枪、弹跳），放到音乐做同样事情的段落。（Lieu）
- 一段里对准一两处关键点，其余不必。（PremiumBeat）
- 音乐停顿留给笑点或最强的画面，停在重拍上，同时给一个视觉重音。全片只用一次。（Film Editing Pro）
- 音乐逐个动作贴合（mickey-mousing）只在笑点处用。（二手）

### 1.4 六个关节的手办怎么演

- 没有脸，情绪全靠身体：整体的蹦、压扁、前倾、歪头，加头顶的气泡。（Lasseter）
- 同一时刻只让一个角色做重要动作，别的压低。（Lasseter）
- 动作摆成侧面，按剪影设计；手挡在身体前面读不出来。（Lasseter）
- 松的附件慢半拍：绒仔的帽子起跳时晚离头、落地时多弹一下。帽子就是他的表情。（Lasseter，本项目）
- 真玩具摆不出来的姿势不做，不做运动模糊。（LEGO Batman 访谈）
- 绒仔走路是迈步走，两条腿一前一后，脚不离地；蹦着走的只有僵尸（那是它们在游戏里的走法）。第一版让绒仔也一蹦一蹦地走，用户否了。高兴得跳起来、被吓得一跳不算走路，可以跳。腿的摆动要跟着走过的距离算，脚才不打滑（`puppet.js` 的 `walkAlong`）。（本项目）
- 会被掀开、弹起来的附件，底下要做完整。绒仔原来的模型只有帽檐外面那一圈头发，帽子压着的头顶是肤色的；帽子一弹起来就露出光头（用户看第三版时指出）。现在在头顶补了一块发顶（`addScoutHair`）。让附件动之前，先把它抬起来看一眼底下是什么。（本项目）
- 设计粗而简单，让毛毡的材质出彩。（Robin Robin 访谈）
- 动作前加小预备（下蹲、后仰），停下后加回稳。（Lasseter）

### 1.5 不穿模

- 站位和走位先对着碰撞盒摆，再看画面。角色比看上去宽：绒仔的头和帽檐有一米一，背包往后伸出六十多厘米，守墓巨像平举的手臂往前伸一米八。
- 家里有些地方本来就过不去：沙发背和书架之间只有九十厘米，门洞宽一米五。戏不要排在这种地方（第一版让绒仔躲在沙发背后、沿着沙发背走，怎么挪都蹭）。
- 倒地的方向也要排：倒下去有一米二长，别倒在茶几、花箱或同伴身上。
- 靠近目标蓄力时，蓄满的毛球会顶进对方身体，两人至少隔一米六。
- 不要为了"躲起来"把角色沉到地板下面，改成从门框、墙角后面探身。
- 贴片（发光的眼睛、光斑）不要靠"关掉深度测试"来保证看得见：那样它会直接画到前面的人身上，看着就是穿模（第二版巨像的眼睛画到了绒仔的帽子上）。照常做深度测试，靠站位和机位让它和前景的人在画面上分开——阁楼那一镜最后是绒仔在画右、黑暗在画左，两者之间隔着十度的空。
- 每次改完走位跑一遍 `__op.clipcheck()`（见 3.5）。它量的是每个部件的轴对齐包围盒，斜着的部件会量大：报出来的每一处都去看一眼，确认是误报才留着，并写明原因。

### 1.6 道具和特效

- 道具要一眼认得出是什么。毛线团是"一圈圈绕起来的线"：一把压一把、方向各不相同、有一截松开的线头。第一、二版的毛球是"球 + 一圈螺旋线 + 一百八十根突刺"，用户说"一个球有些突刺"，还把它看成了炸弹。现在的做法见 `library/games/rongboy-runtime.js` 的 `createWoolBall`：表面的线是算出来的贴图（颜色 + 法线），最上面那一把线和线头是真的几何体，游戏和片子用同一颗。（本项目）
- 大白天里的爆炸不能只靠发光：加色混合的光球叠在亮背景上只剩一个淡淡的泡泡。要用不透明的东西——一大团棉絮、往外飞的线头、被掀飞的人，再加一下闪光和贴地的冲击波。（本项目：用户说手雷"没有啥爆炸效果"）
- 因和果要在同一个画面里、按顺序各占一拍：手雷落地 → 它们低头看 → 炸飞。第二版手雷飞出了画外、落点被前景的大积木挡住，炸完僵尸原地套了三个圈，用户说"剧情也不搭"。（本项目）
- 前景里不要有和这场戏无关的大件（第二版手雷镜头前面挡着两块游乐积木）。选机位先看场地里有什么。（本项目）
- 落在地上的东西（线头、倒下的积木）在这个镜头里不要消失，留着就是"刚才发生过什么"。（本项目）

## 2. 主界面准则

- 主界面是玩家对基调的第一口，而且会反复看到，要耐看。（GamesRadar）
- 在吸引人和尽快开玩之间取平衡：别让玩家慢下来。华丽到卡顿是在害游戏。（GamesRadar）
- 把菜单当第一章：能在标题画面教会核心动词最好（文章里的例子是把菜单上的锁扣射掉才能开始）。（Game Developer）
- 选项少，不穿过多层菜单就能开始。（Game Accessibility Guidelines）
- 整个界面用和玩法同一种输入就能操作。键盘和手柄都能选地图、出发、跳过开场；手柄的 ✕ 是确定。（同上）
- 键盘惯例：上下选（可循环）、Enter 确定、打开时焦点在第一项。（W3C）
- 开场和过场要能立刻跳过。（GameAnalytics）
- 浏览器不让没按过键的页面出声，所以带声音的开场必须在一次按键或点击之后才开始。（MDN）

### 2.1 游戏界面的字和按键

主菜单、选关、设置、练习、挑战簿和实战提示共用 `assets/rongboy/rongboy-interface.css`。简体中文用站酷快乐体，西文和数字用 Fredoka。按键提示用浅色圆键帽，主动作和当前选项用金色布贴，键盘焦点有独立的外框。字库离线打包为 WOFF2，共约 190 KB，中文子集覆盖这版界面文案。改完以 CrazyGames 的 821×462 和 907×510 嵌入窗分语言检查控件和键盘流程。

## 3. 这部开场片：《嘘——》

### 3.1 先回答的五个问题（story-design 第 1 节）

1. **讲的是什么**：这个世界是软的，但你得轻手轻脚——因为一声响，全屋都醒。
2. **想要什么**：阁楼上那只毛线篮（第一关的任务）。**需要什么**：学会小心。片子里他没学会，所以才好笑。
3. **赌注**：打倒一只很容易，惊动一屋子就得靠整个军火库。
4. **对手**：毛绒僵尸不坏，只是在睡觉，被吵醒了有起床气。
5. **带走什么**：手痒（我也想从背后给它一球）和好奇（他身后门里那是什么）。

### 3.4 对照检查

对的是 film-grammar 第 8 节和本文第 1 节。量化的几项是按分镜数据算的，其余是看静帧（每镜至少一张，动作多的镜头抽 8–12 帧）判断的。

| 项 | 结果 |

没做到或没验证的：

- **没有人看过成片**。我只能看静帧，动作的快慢、节奏对不对拍、声音大小合不合适，都要用户看了才知道。
- 音效是程序合成的（呼噜、"嘘"、积木、感叹号是这次新写的），没有人听过。
- 09 号镜头里绒仔在门厅最远处，很小，几乎看不见；这个镜头的主角是僵尸，没有处理。
- 11 号镜头里僵尸在太阳下颜色偏浅（游戏里的花园也是这样），曝光压到了 0.8。
- 17 号镜头的黑是黑幕叠出来的，不是真的没有光：地板在黑幕前面那一截仍然是亮的，靠整体压暗曝光（0.34）遮过去。
- 引擎的 `tools/shotcheck.sh` 没有跑：它假设全片一个场景、一对主角，这部片子换了三张地图。分镜页面按它要的接口给了数据（`window.__film`），工具要改了才能用。

### 3.5 怎么放、怎么导出

- 入口是 `dist/rongboy-op.html`，按任意键或手柄 ✕ 开始，任意时候按 Esc / Enter / 空格或手柄任意键跳过，播完进 `rongboy-mission.html?from=op`（主界面从黑场淡入）。手柄不能替浏览器的自动播放策略"按那一下"：只用手柄时片子可能被拦下，页面会改成请玩家按一次键盘。
- 默认放 `rongboy-op.mp4`（和页面放在一起）。这台开发机（Intel Mac，Radeon Pro 5300M）1080p 实时渲染一帧要 60–118 毫秒，所以默认不实时。`?live=1` 是实时渲染：要先搭三张地图，等十几到三十几秒，慢的显卡会自动降画质。找不到 mp4 时自动走实时。
- 每一帧都是引擎画的。重新导出：`npm run build && scripts/op/export.sh`，产物 `assets/rongboy/op/rongboy-op.mp4`（build 时拷到 `dist/`）。30 帧每秒、1920×1080，在这台机器上约五分钟。
- 改片子：分镜和走位在 `scenes/rongboy-op/film.js`（每个镜头一段，时间是片子的绝对秒数），摆姿势的工具在 `puppet.js`，三张地图和演员在 `stage.js`，片名卡在 `title.js`，声音在 `audio.js`。
- 看某一刻的画面：`node scripts/build.mjs --serve --port 5193 rongboy-op`，打开 `rongboy-op.html?export=1&w=640`，控制台里 `await __op.still(21.0, 'x')` 存成 `shots/x.jpg`。
- 查穿模：同一个页面里 `__op.clipcheck()`，返回 `[{ shot, who, into, from, to, depth }]`（谁的哪个部件、伸进了什么、从几秒到几秒、最深多少米）。
- 换配乐要重新对拍：`film.js` 开头的 `BEAT`、`B0` 和每个镜头里的 `beat(n)` / `bar(n)`。

## 4. 主界面

2026-11-17 用户试玩修订：选图不得重载整个3D场景。主界面改为轻量独立页面，左边直接选地图，右边显示按真实关卡绘制的楼层预览。选图只更新本页状态；确认出发后才打开 `rongboy-play.html`，显示加载界面、实际阶段进度，再直接进入第一人称。去掉绒仔与僵尸走开、推镜的出发演出。

- `rongboy-mission.html`：四张地图及试战入口；W/S、A/D、方向键或鼠标选择，Enter 出发；手柄用十字键 / 左摇杆选择，✕ 出发。
- 预览是构建时生成的静态SVG，不加载角色、WebGL或完整场景；新增地图后由构建自动更新。
- 加载界面先绘制，再初始化选定场景、布偶与材质。失败时提供返回选图，不永久遮挡页面。
- 游戏结束返回选图，保留刚才的地图。开场片与图鉴继续可访问。

### 4.3 第一人称主菜单与分层选关 · 2026-11-19

主入口显示院门和线轴枪。上下选「选关、设置、练习、图鉴」，确认后进入相应页面。选关页横向切换四张图片，确认后才加载关卡；暂停和结算回到刚玩的地图。父子页面共享 Esc / ○ 返回约定。旧的 `?level=地图` 直达选关，`?level=training` 直达兵种选择。

设置页保存声音、画质及减弱镜头晃动，实战入口读取它们。图鉴和单兵种选择按需打开透明 3D 预览，角色来自定稿的三组模型。图鉴可切换正、侧、背三档，并从详情进入对应兵种试战。练习先进入就绪画面，玩家确认后开始接敌。退出回传入口与兵种，保留原来的选择。

正式菜单使用 `assets/rongboy/menu-plates/` 中的 WebP 场景底图。所有菜单、选择焦点、设置值和加载进度由实际页面绘制。

## 5. 最容易犯的错

1. 用一串慢速空镜或 logo 开头，10 秒内看不出是什么游戏。
2. 只有"东西在动"，没有"玩家做了什么 → 发生了什么"。
3. 一个镜头塞两件事，或两个角色同时抢戏。
4. 全程一个能量级，没有谷。
5. 最炫的武器一开始就用掉。
6. 每个拍都切；或者完全不对拍。
7. 音乐停顿用太多，笑点失效。
8. 动作正对镜头、叠在身体前面，剪影读不出来；没有预备和回稳。
9. 帽子、围巾和身体同步刚性移动，玩具感变成僵硬感。
10. 标题画面选项多、要穿几层才能玩；开场不能跳过；没等按键就播，结果没声音。
11. 让主角也像僵尸一样蹦着走；第一个画面用怼脸特写；站位不看碰撞盒，结果蹭家具、压同伴。
12. 道具认不出是什么（带刺的球被看成炸弹）；爆炸只有一层光；因和果不在一个画面里；为了"看得见"关掉深度测试，结果画到了前面的人身上；标题卡上多写一句话。
